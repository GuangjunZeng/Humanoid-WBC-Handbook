# ULC: Sequential Skill Curriculum for One Fine-Grained Loco-Manipulation Policy

[中文版](../ulc-2507.06905v2.md)

Sources: [arXiv:2507.06905v2](https://arxiv.org/abs/2507.06905v2) · [official project page](https://hellod035.github.io/ULC/)

Review scope: the complete 13-page paper and appendix. At the review snapshot the official page still marked code as “Coming Soon,” so no third-party repository is treated as the paper's implementation.

> In one sentence: ULC combines root velocity, root height, torso orientation, and arm-joint goals in one actor, while sequentially enabling skills and adding learned residuals to programmatic arm targets to reduce early multi-objective interference.

Key terms are unified loco-manipulation control (统一移动操作控制), sequential skill curriculum (顺序技能课程), residual action (残差动作), feedforward target (前馈目标), quintic interpolation (五次多项式插值), command-delay randomization (命令延迟随机化), center-of-mass projection (质心投影), and multi-objective interference (多目标干扰).

## Engineering problem

Concatenating more commands into an observation does not make a unified controller easy to learn. Velocity rewards improve early, while precise torso and arm goals become meaningful only after stable support. If all objectives are strict from the start, progress on one can destroy another—like learning to cycle, carry water, and aim at the same time.

Upper-body precision also benefits from known programmatic targets. Asking a network to regenerate an absolute arm pose wastes a reliable feedforward signal. ULC lets the command specify intended joint angles and trains only a dynamic correction. This resembles following a mapped route while using small steering corrections for actual road conditions.

Deployment commands introduce delay, stale frames, and abrupt transitions. Quintic interpolation and randomized command release shape the interface distribution seen during training. They cannot by themselves repair clock drift, dropped packets, or unreachable command combinations.

## Core insight

ULC encodes training order as an observable curriculum rather than a manual one-off configuration switch. A moving reward statistic must pass a threshold before another command family is enabled, and earlier objectives remain active. The mechanism therefore asks the policy to expand its interface without forgetting its base skill.

Residual arms separate user intent from balance compensation. The programmatic target preserves what the upper level requests; the learned residual handles payload and body-acceleration effects. Target and residual can then receive distinct magnitude and rate limits.

One network still expands fault propagation. An anomalous arm command can disturb gait through shared dynamics, so acceptance testing must include isolated, joint, and abrupt commands—not only smooth showcase trajectories.

## Method: input → processing → output

One 29-dimensional Gaussian policy tracks root linear/angular velocity, root height, three-axis torso orientation, and bilateral arm joint angles. Leg and torso actions are scaled around a default pose. Arm output follows `q_final = q_desired + q_processed`, making the desired pose feedforward and the policy output residual.

Training enables velocity, then height, then torso and arms according to sliding-reward thresholds. Quintic interpolation smooths random targets; delayed command release simulates deployment timing. Wrist payload is randomized from 0–2 kg, and a reward projects CoM toward the midpoint of both ankles. Six frames of observation history are used with 0.005 s simulation step and decimation four, corresponding to a 50 Hz policy.

The command is a typed contract with different units and frames. A reproduction must record Euler convention, root frame, arm order, range, interpolation boundary, delay distribution, and timeout behavior before training.

## Strongest experiment

Table V is stronger than the robot demonstrations for causal interpretation because it removes components within one training family. It supports the narrow conclusion that curriculum ordering, feedforward-plus-residual arms, and the balance term each contribute to the tested unified policy.

Robot tasks with toys and a refrigerator show that a teleoperation chain can call the interface, but they omit full trial denominators and failure categories. A reproduction must report approach, stable contact, manipulation, object retention, and exit stages instead of labeling one complete video as a task-success distribution.

## Paper-to-implementation status

As of 2026-08-10 the paper pointed to the project page, but its code control still read “Coming Soon”; there was no unique author repository, commit, or license. Curriculum thresholds, command queues, quintic interpolation, and residual-action symbols therefore cannot be audited at file/function level.

An independent implementation should label every curriculum state transition, command-buffer decision, and residual formula as a reproduction choice. A similarly named community repository cannot fill the official-code field.

## Limitations and safety boundary

The Author-stated limitation is that velocity-style lower-body commands cannot express complex MoCap leg patterns. Independent limitations are one three-DoF-waist G1, mainly qualitative real tasks, simulated 2 kg payload versus static 0.5/1/1.5 kg hardware comparisons, and a simplified CoM target at the ankle midpoint rather than a support-polygon or ZMP constraint.

Quintic interpolation limits ideal target derivatives but cannot fix stale commands or unreachable combinations. The deployment stack must independently validate command age, amplitude, rate, joint feasibility, torque, contact, and thermal state.

Paper ranges and loads are not safe settings for another robot. Hardware requires robot-specific limits, emergency stop, a separated test area, and task-level failure exits.

## Bounded engineering takeaway

For unified multi-objective training, make curriculum order, feedforward-plus-residual action, deployment-delay modeling, and payload balance independent ablations. Evaluate command range, command accuracy, and simultaneous-command degradation separately. Define what the policy should preserve first when height, torso, arm, velocity, and payload goals cannot all be satisfied.

## Reproduction and acceptance checklist

Produce a command dictionary before weights. Save each curriculum stage, threshold, old/new skill metrics, and rollback. Compare absolute and residual arms under equal final joint limits and total amplitude, logging desired, residual, and final targets. Calibrate delay/drop/repeat/jump distributions from actual teleoperation logs. Test a grid near command boundaries and combined stress—payload, speed reversal, low root height, large torso orientation, and arm extremes—while logging support, torque, current, heat, falls, takeovers, and recovery time.
