# AMP：把动作数据学成风格奖励，而不是逐帧选择参考轨迹

[English version](en/amp-2104.02180v2.md)

来源：[arXiv:2104.02180v2](https://arxiv.org/abs/2104.02180v2) · [IsaacGymEnvs 官方实现固定提交](https://github.com/isaac-sim/IsaacGymEnvs/tree/aeed298638a1f7b5421b38f5f3cc2d1079b6d9c3)

解读范围：完整 20 页论文与附录；本文只保存原创分析、图表定位和代码链接，不保存论文全文、动作数据或模型权重。

> 一句话结论：AMP 用判别器区分“动作数据中的短时状态转移”和“策略生成的转移”，把判别结果作为 task-agnostic style reward，再与任务奖励联合训练；它免去显式 clip 选择与 phase 同步，但把系统可靠性转移到判别器特征、数据覆盖与对抗训练稳定性上。

术语导航：对抗运动先验（Adversarial Motion Prior, AMP）、判别器（discriminator）、风格奖励（style reward）、任务奖励（task reward）、状态转移（state transition）、非结构化动作片段（unstructured motion clips）、经验回放（replay buffer）、梯度惩罚（gradient penalty）、模式坍塌（mode collapse）、动作跟踪（motion tracking）。

## 工程痛点

DeepMimic 式跟踪要为当前状态选定参考 clip 和 phase。动作库扩大后，系统还需决定何时走、跑、转身、击打或起身；若 clip 选择器错误，跟踪器再精确也会做错动作。AMP 希望让任务奖励决定“做什么”，动作数据只约束“动作看起来是否属于该风格”。

核心难点是自然动作没有简单解析代价。关节平滑、能耗和直立不能排除僵硬小碎步或不自然过渡。AMP 用学习到的判别器替代人工风格指标：判别器不指定逐步轨迹，而是根据参考数据分布判断状态转移是否像动作样本。

## 方法主线：策略与判别器共训

策略接收角色状态与任务 goal，产生动作并优化 `w_G r_G + w_S r_S`。`r_G` 是面向目标方向、速度、击打位置等任务奖励；`r_S` 来自 AMP discriminator。二者分工使动作库不需要任务标签，任务数据也不必包含目标场景的完整轨迹。

判别器输入不是任务目标，而是根相对姿态、速度、关键点等连续状态转移。演示转移标为真，策略/replay 转移标为假；least-squares objective 训练判别器，输出再映射到有界 style reward。只看单帧容易让静态姿态冒充动作，加入速度与连续转移能区分滚动和躺地。

训练过程交替更新：策略 rollout 产生任务与风格回报；演示缓冲抽动作转移；策略当前和历史 replay 作为负样本；判别器通过 gradient penalty 等正则避免对有限演示过拟合。策略和判别器共同变化，奖励不是固定函数，因此训练日志必须同时监控两者。

论文 Algorithm 1 还隐含一个常被丢失的数据契约：演示样本与策略样本必须使用同一个观测映射 `Φ(s)`，且连续状态的时间间隔相同。若动捕数据是 30 Hz、策略控制是 60 Hz，直接把相邻帧都当成同类转移，判别器可以仅靠速度尺度识别来源。复现时应先重采样并校验一步时间，再讨论对抗损失。

AMP 不显式选择 clip。若任务要求远目标，策略在 locomotion 数据先验下可从走切到跑；击打任务的数据同时含走和 punch 时，可先接近再击打。所谓“自动组合”是任务回报在风格可接受区域内选择状态转移，不等于系统学到可解释的离散技能图。

## 最有说服力的实验

最有价值的是数据集内容改变会系统性改变任务行为：只含走路时策略倾向走，只含拳击时无法合理接近目标，走+拳击数据则产生接近后击打。这隔离了 motion prior 的贡献，说明复合动作并非仅由 task reward 自发产生。

单片段对照表明 AMP 不依赖 phase 仍可达到接近手工 imitation reward 的动作质量，并避免策略/参考速度不一致导致的失同步。优势不是精确复刻某一帧，而是只要短时转移在数据分布内即可调整时序。

这一优势也决定了评估方式：不应只对某条参考做逐帧误差，否则会把合法的速度调整误判为失败。更合理的验收是同时报告任务成功、物理约束、动作特征分布与人工检查，并保留过渡失败的连续视频。论文展示的是任务下的动作品质，不是与唯一标准轨迹的像素级重合。

负面消融比展示视频更重要：判别器缺速度会接受不动姿态，缺梯度正则更易训练不稳。对抗奖励可能出现准确率极高但策略无梯度、准确率接近随机但风格仍差等状态，不能用 discriminator loss 单指标判断成功。

## 适用边界与局限

作者明确指出判别器会受策略任务分布影响，可能妨碍 motion prior 跨任务复用；实验主要研究技能的时间组合，空间上同时组合多种动作仍有限；对抗训练仍可能 mode collapse。所有结果是物理仿真角色，没有机器人执行器、感知或 sim-to-real 实验。

独立工程判断是：AMP 学的是数据支持集的“像”，不是安全或物理最优。动作库若含足滑、碰撞、错误根高度，判别器会奖励这些模式；动作库缺少恢复，策略在任务压力下可能选择先验外但高回报行为。数据审计与 task-side 约束仍不可省略。

判别器观测通常使用规范化、根相对特征。训练/部署若旋转表示、关节顺序、历史步长或统计量不一致，风格奖励会失真。对新机器人重定向后，判别器需重新训练；不同形态不能直接共享输入维数和数据分布。

还要区分“判别器识别不出”和“策略真的覆盖数据”。在两者容量不平衡时，近似随机的判别准确率可能只是分类器过弱；过高准确率又可能使策略获得的奖励几乎全为零。除了 loss，应定期用留出演示、打乱时序的负例和人工注入异常转移检查打分曲线，才能判断奖励是否有意义。

## 可执行但有边界的结论

当动作库无任务标签、又不想维护 clip selector 时，AMP 是有价值基线。先用单一动作集验证判别器确实区分真实/破坏性转移，再加入简单 heading task，最后逐步扩充动作库；不要从大而杂的数据和复杂任务同时开始。

调试应画 task reward、style reward、判别真/假得分、gradient penalty、演示/策略特征分布、动作类别覆盖和任务成功。可以把两个奖励看成两位评审：一位只看任务完成，一位只看动作风格；总分相同可能来自完全不同的意见，必须分别查看。

增加新动作时，先做数据集间的离线对照：根高、质心速度、足接触、关节速度与关键点分布是否形成完全分离的簇。若是，判别器容易把动作类别当作真假捷径，策略在类别过渡处会缺乏奖励支持。先补过渡数据或分阶段扩充，通常比盲目加大网络更容易定位问题。

最小可诊断试验应使用一个短动作集和一个只要求朝向/速度的任务，并固定演示批次、策略批次与 replay 比例。先检查未训练策略、随机打乱的演示和真实演示是否有正确得分排序，再启动联合训练。若这一小测试都无法区分连续动作和时序打乱，问题在特征或数据，而不在任务奖励。反之，若判别排序正确而策略仍不运动，才进一步检查 style weight、奖励截断和 PPO 更新。这种分层验收能避免将数据管线错误误判成对抗训练不稳定。

## 复现与验收清单

锁定动作数据、重定向、判别特征、历史长度、归一化、演示/策略/replay 比例、网络、梯度正则、两类奖励权重和随机种子。至少做无 velocity、无 gradient penalty、task-only、style-only、显式 tracking 五组对照，并报告任务指标、风格人工/检索指标和失败模式。

若迁移到人形实机，必须额外建立机器人可行数据筛选、动力学随机化、状态估计、控制延迟、关节/速度/力矩限幅和急停保护。本文没有实机证据，不能因动作“自然”就跳过仿真—硬件分阶段验证。

数据集版本也必须进入 checkpoint 元数据。因为 AMP 奖励由数据学得，替换或清洗一个 clip 就等于改变了奖励定义；若只记录策略权重而不记录 motion manifest、重定向版本和判别器权重，后续即使任务回报相同，也无法解释风格变化的来源。

验收报告应单列动作数据外的策略行为，例如超出演示速度、非预期接触或长时静止。这些样本不能只因 discriminator reward 高就标记合格；它们正是检验判别器是学到动作结构，还是只学到有限数据捷径的反例。

> **工程判断**：AMP 省掉的是显式参考选择，不是工程约束；风格判别器能扩大任务自由度，也会忠实放大动作数据中的偏差。

因此，方法验收的最小单位是“数据版本+判别器+策略+任务”，不是一个孤立的策略权重文件，也不是一段精选视频或单一总回报。
