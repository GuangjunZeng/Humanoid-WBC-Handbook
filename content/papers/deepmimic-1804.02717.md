# DeepMimic：参考动作、任务目标与课程机制如何共同学出高动态物理技能

[English version](en/deepmimic-1804.02717.md)

来源：[arXiv:1804.02717](https://arxiv.org/abs/1804.02717) · [固定提交的官方代码](https://github.com/xbpeng/DeepMimic/tree/1f915c52fcd4b95b5f5f15b759ae91bd81e9a801)

解读范围：完整 18 页论文、补充算法/训练曲线，以及官方 imitation reward 与 PPO 实现。本文是物理角色仿真的经典锚点，不把模拟 humanoid character 误写成真实机器人。

> 一句话总结：DeepMimic 以 phase-conditioned 状态和 PD target 动作联合优化动作模仿与任务目标，并靠 reference state initialization（RSI）和 early termination（ET）让翻腾、起身和格斗可学；它证明参考动作能引导探索，却没有证明策略可直接 sim-to-real。

术语导航：示例引导强化学习（example-guided reinforcement learning）、动作模仿（motion imitation）、参考状态初始化（reference state initialization, RSI）、提前终止（early termination, ET）、相位变量（phase variable）、比例—微分目标（PD targets）、复合策略（composite policy）、技能选择器（skill selector）与近端策略优化（proximal policy optimization, PPO）。

## 工程痛点

后空翻、旋踢和起身的奖励非常稀疏。只奖励“最后站稳”时，随机策略几乎遇不到成功轨迹；逐关节播放 mocap 又不会根据扰动调整，且参考动作可能与角色形态不完全一致。工程目标是借参考动作缩小探索空间，同时保留闭环物理适应。

一个动作片段也不是完整课程。若 episode 总从第一帧开始，策略早期只见起始姿势，后半段高价值状态永远到不了；若跌倒后继续采样，buffer 被大量无意义挣扎占满。RSI 和 ET 像把训练书随机翻到不同章节，并在明显答错后及时换题。

更难的是“像参考动作”与“完成任务”会冲突。投球若只模仿，手可能漂亮却投不中；只奖励命中，角色可能抱球跑到目标。需要把风格先验与任务目标显式组合，并用消融判断两者各自贡献。

## 核心洞察

策略状态包含角色相对局部坐标的 link pose/velocity 和归一化 phase；动作是 30 Hz 的关节 PD target，Bullet 以 1.2 kHz 仿真。网络两层 1024/512。相位相当于给策略一张“参考动作进度条”，减少从本体状态推断时序的负担。

imitation reward 分解为 pose、velocity、end-effector 与 center-of-mass，论文权重约 0.65、0.10、0.15、0.10，再与 task reward 加权。多个指数项让小误差平滑变化，但尺度和权重仍是人工设计，不是从数据自动发现。

RSI 从参考动作任意时间初始化角色，使策略从训练早期就看到全片段；ET 在头或躯干等关键部位异常接触时终止。二者形成隐式课程：先学每个局部邻域如何回到参考轨迹，再串成完整技能。

## 方法主线

每个 reference clip 提供 `q̂_t` 与 `q̇̂_t`。策略接收当前状态和 phase，输出 PD 目标，环境计算 imitation 与 task reward。PPO 使用 batch 4096、minibatch 256、`γ=0.95`、`λ=0.95`、clip 0.2；典型技能约 6000 万样本、8 核 CPU 两天。

单技能之外，multi-clip reward 对多个片段取最大模仿回报；skill selector 用 one-hot 指定技能；composite policy 从多个已训练 value function 中选择。多技能不是一个统一 latent space，而是几种显式集成策略，各自有切换和覆盖边界。

任务实验包括目标朝向、投掷、击打和障碍。模仿奖励提供自然动作，任务奖励让动作针对环境调整。不同形态包括 34 DoF humanoid、Atlas、T-Rex 与 dragon，说明方法不绑定单一骨架，但所有证据仍在模拟器。

## 最有说服力的实验

最强实验是任务消融。它揭示 reward 的真正职责：reference 不是为最高任务分数，而是限制解的行为形态；goal reward 让动作适应目标。strike 两者互补，throw 则展示风格—成功 trade-off，避免“总分最高就是最好”的误判。

扰动实验也有信息：0.2 秒骨盆推力下，running 向前约 720 N、spinkick 不同方向约 690/600 N 仍可恢复。但这是模拟角色、特定持续时间和状态，不能换算成机器人允许外力。

## 论文—代码映射

固定提交 `1f915c52fcd4b95b5f5f15b759ae91bd81e9a801` 中，`DeepMimicCore/scenes/SceneImitate.cpp::cSceneImitate::CalcRewardImitate` 计算 pose、velocity、end-effector、root/CoM 误差并用指数项组合，直接对应论文模仿 reward。

`learning/ppo_agent.py::_build_losses` 和 `_train_step` 实现 ratio clip 0.2、advantage clip 5、actor clipped surrogate、critic loss 与优化器。配置、动作文件与 C++ 环境共同决定实验；只运行 PPO 脚本不会自动得到论文动作。

## 局限与工程判断

作者明确指出 phase 固定了动作节奏，难以自由变速；动作片段集合小；PD gains 人工设置；每技能训练需要天级时间；状态距离和 reward 权重手工设计。多片段混合可能只采用部分 clip，组合策略仍需工程选择。

独立工程局限包括：大多结果是单 seed；早终止改变访问分布并可能掩盖恢复能力；mocap 足接触与动力学不完全一致；1.2 kHz 仿真和 ideal PD 不代表真实执行器；没有传感噪声、时延、热与结构冲击模型。

硬件安全上，翻腾/踢击策略不能因“robust push”就直接实机。需要机器人专用重定向、接触修复、扭矩/速度/功率/碰撞约束、落地区域和保护装置。先从低幅度、悬挂或软体平台验证，任何 phase 跳变或 estimator reset 都应触发降级。

## 可执行但有边界的结论

DeepMimic 的经典配方是：reference reward 规定解的风格，task reward 规定任务，RSI 覆盖整段动作，ET 控制失败样本。四项缺一时都可能得到“分数不错但动作错误”或根本学不到的策略。

对现代 WBC，应把 fixed phase 逐步替换为可调速 phase、goal-conditioned representation 或 phase-free motion prior，并保留模仿与任务两个独立指标。不要用一个加权 return 掩盖二者冲突。

## 复现与验收清单

固定 Bullet、角色 XML、动作 clip、帧率、PD gains、reward 权重、PPO 参数、提交与 seed。单元测试 phase wrap、reference interpolation、quaternion distance、ET contact 与 RSI 时间采样；验证 30 Hz policy 与 1.2 kHz substep 的比例。

复现 RSI/ET 消融、Table 4 任务对照与多 seed 学习曲线，分别报告 pose/end-effector/CoM 误差、任务成功、跌倒、能耗和不自然捷径。对 reference 加速、减速、接触偏移与形态变化做外推测试。

机器人迁移前，先用真实执行器模型和状态估计噪声重训/评估，建立扭矩、关节速度、足冲击与自碰撞 envelope。真机逐级扩大动作幅度，保留系留、急停、场地隔离和机械/热监测，不能把模拟字符的外力数字当安全阈值。

## 进一步工程审计

参考动作预处理决定了奖励上限。动作片段的根方向、地面高度、速度和循环边界若不连续，策略会同时学习目标动作与数据修补。应在训练前检查足端穿地、滑移、关节速度尖峰和首尾姿态差，对修复步骤保存前后对照。起身和翻腾并非周期动作，不能为了方便强行首尾拼接；行走循环则需验证接触相位和根位移连续。

相位输入虽然降低学习难度，却会造成外部时钟依赖。角色被大力推迟后，身体状态可能落后于参考相位，策略仍被要求追赶未来姿态，从而输出激烈动作。应测量相位误差与恢复力矩，测试暂停、变速和相位重同步。现代实现可由状态估计相位或允许策略调整进度，但这又需要防止策略通过停滞相位逃避任务。

模仿误差的尺度必须按形态和关节语义重新校准。统一角度误差会让大量小关节主导总分，末端位置误差又可能放大长肢体影响。对机器人应分别设置根、支撑腿、摆动腿和上肢指标，并把关节限位、足接触与执行器能力纳入评价。论文权重是经典起点，不是所有角色和任务的默认正确答案。

参考状态初始化会改变部署时访问的状态分布。训练中策略经常从动作中段的理想状态开始，真实部署却通常从中性姿态或上一个技能结束状态进入。应额外训练和测试技能入口，记录从实际初态到参考轨迹的收敛时间与失败；多技能系统还需对每一对技能出口—入口做组合测试，不能因为单技能回放成功就假设任意切换安全。

提前终止也可能掩盖最需要的恢复能力。若躯干触地立即结束，策略从未学习从轻微跌倒回到动作；若终止过晚，大量无用样本降低效率。建议区分不可恢复硬终止、允许恢复软失败和任务超时，并报告各自频率。恢复策略可以独立训练，但切换条件、状态重置和相位初始化必须成为完整系统的一部分。

任务消融提醒我们建立双重验收。任务成功衡量球是否命中、方向是否到达；动作质量衡量姿态、接触、能耗和自然性。两类指标不能提前加权成一个总数，否则只任务投掷的捷径可能看似最优。评审应保留散点或帕累托边界，明确选择了多少任务性能来换取可接受的动作形态。

训练成本要按技能和随机种子完整记录。单次两天容易让团队只保留成功模型，忽略失败种子、奖励敏感和超参数试验。应固定小型诊断动作，先验证状态、奖励、相位和控制频率，再启动完整高动态训练；训练曲线异常时保存初始模型与轨迹，防止只看最终视频无法定位早期探索问题。

机器人使用动作库时，还需将“视觉相似”与“物理相似”分开。人体参考可能用手或膝承受机器人结构不允许的冲击，策略即使姿态漂亮也会损伤硬件。对每个动作建立允许接触部位、峰值冲量、落地区域和失败姿态，先在高保真仿真统计，再在保护条件下小幅验证。模拟人物能站起来，只说明算法搜索到物理解，不代表特定机体承受得住。

多技能集成还应检查技能之间是否共享一致的状态与动作规范。不同模型若使用不同观测归一化、关节顺序或目标尺度，选择器在切换时即使选对策略也会发送错误动作。所有技能应通过同一接口契约，检查点携带角色资产、观测版本和动作含义；加载时逐项验证，不匹配就拒绝运行。切换测试不仅看最终技能能否完成，还要看过渡期间的姿态、接触、力矩和相位是否连续。

参考动作的版权和来源也需记录。公开演示片段、商业动捕和自行录制数据的再分发条件不同，训练得到的模型是否可公开也可能受条款影响。数据清单应保存来源、许可、处理步骤和哈希，页面中的关键图只用于评论性解读。可复现工程不能以无法追溯来源的动作文件为核心，否则技术结果即使成功，也难以长期维护或安全共享。

最终报告应同时展示成功和失败轨迹。对每个动作列出完成率、中断阶段、偏离参考的位置、接触异常与任务捷径，并给出多次独立训练范围。只挑最顺畅的视频会隐藏策略最重要的边界；保留失败分布则能指导下一轮动作清洗、奖励调整和恢复策略设计，使参考动作真正成为可审计的工程规格。

> **工程判断**：参考动作最有价值的作用不是让策略逐帧复制，而是告诉稀疏任务奖励“哪一种成功才是我们想要的成功”。
