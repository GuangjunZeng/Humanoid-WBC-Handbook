# Crocoddyl：为什么高动态多接触优化要先允许轨迹“不完全可行”

[English version](en/crocoddyl-1909.04947.md)

来源：[arXiv:1909.04947](https://arxiv.org/abs/1909.04947) · [固定提交的官方代码](https://github.com/loco-3d/crocoddyl/tree/46974c3c49ed956e41f8f95a329cf8537af7550b)

解读范围：完整 7 页论文、FDDP 求解器、接触前向动力学 action model 和双足步态示例。

> 一句话总结：Crocoddyl 用高效解析导数、多接触动力学和可行性驱动微分动态规划（Feasibility-Driven Differential Dynamic Programming, FDDP）在几十次迭代内求解动态动作；论文为突出算法而有意忽略摩擦锥和力矩约束，因此毫秒级轨迹不能直接等同于可安全执行轨迹。

术语导航：多接触最优控制（multi-contact optimal control）、微分动态规划（Differential Dynamic Programming, DDP）、动态 gap（dynamics gap）、可行 rollout（feasible rollout）、前向动力学（forward dynamics）、冲击模型（impact model）、李群状态流形（Lie-group state manifold）与解析导数（analytical derivatives）。

## 工程痛点

经典 WBC 的轨迹优化同时面对刚体动力学、接触约束、切换冲击和非欧式姿态。标准 DDP 每次 forward pass 都从一个状态完整积分下一步，因此轨迹始终动力学可行；但在跳跃、翻转等问题的差初始化下，这条可行 rollout 可能立即远离解，导致 line search 找不到下降方向。

高动态问题像从两端拼一座桥：初始轨迹的每个节点可能各自接近合理姿态，却尚未由动力学连续连接。经典 DDP 要求从第一步开始把整座桥一次拼完；FDDP 允许节点之间暂时留下 gap，再在下降过程中逐渐收口。这不是放弃动力学，而是把可行性作为优化进度的一部分。

另一个瓶颈是接触动力学导数。若每个时间点都数值差分刚体与约束方程，计算和噪声会迅速增长。Crocoddyl 将 contact forward dynamics、impact 与 SE(3) 状态运算写成可组合 action models，并利用稀疏解析导数，使一次 backward pass 足够快。

## 核心洞察

FDDP 维护 shooting nodes 之间的缺陷。line-search 步长小于 1 时，不强制完全闭合 gap，而是按步长收缩；接受全步长时 gap 才闭合。其价值类似数值求解里的“软着陆”：先让代价和状态进入正确吸引域，再恢复严格动力学连续。

Equation 15–20 把 defect 纳入 forward pass 与期望改进。backward pass 仍构造局部二次价值函数和反馈增益，forward pass 则同时更新控制、状态与 gap。可行轨迹附近它退化回普通 DDP，因此无需维护两套求解器。

Crocoddyl 还把多接触与冲击统一为 action model。Equation 2–6 描述 holonomic contact force、受约束加速度和冲量；状态在 SE(3) 等流形上用 `integrate` 与 `diff` 运算，避免把旋转粗暴当欧式向量相加。

## 方法主线

用户提供机器人状态、控制、接触序列、每节点 cost 和对应 action model。接触前向动力学通过质量矩阵、偏置力与接触 Jacobian 联立求加速度和约束力；contact gain/loss 节点用 impulse model 将碰撞前速度映射到碰撞后速度。

求解器从可能不可行的 state/control warm start 出发。backward pass 计算 Q 函数导数、feedforward 和 feedback 增益；forward pass 对候选步长 rollout。与经典 DDP 不同，它保留并收缩旧 gap，使高动态动作早期无需接受灾难性的完整可行 rollout。

成本可组合质心、足位姿、状态和控制正则等 residual。论文中四足步态共享权重，双足使用相近权重；切换相位使用 impulse model。最终输出状态、控制、接触力与可用于 receding-horizon 控制的局部反馈策略。

但论文评测为隔离 FDDP 效果，有意不加入摩擦锥和力矩上下界。它说明这些可通过惩罚加入，却没有在报告动作中给出硬不等式可行证明。对真实 WBC，这不是实现细节，而是决定轨迹能否执行的基本边界。

## 最有说服力的实验

最强证据是 Figure 2 的 gap/代价曲线和多种动态动作 12–36 次迭代的结果。相同初值下，经典 DDP 的完整可行 rollout 在跳跃中容易走向差区域，而 FDDP 保留 gap 后收敛。它支持求解策略对差 warm start 更稳健。

它不支持“轨迹已满足实机约束”。作者明确写明为评估 FDDP 忽略 friction-cone constraints 与 torque limits。若复现用于硬件，必须另报不等式违例、接触裕量、峰值力矩、模型误差扰动和闭环跟踪，而不能只复现运行时间。

## 局限与工程判断

作者明确指出实验忽略摩擦锥和力矩限制，未来需要不等式约束处理。论文的动态动作主要在仿真模型中优化，没有给出完整实机统计；固定接触序列也由用户预先提供，求解器没有解决接触发现。

独立工程局限包括：解析导数依赖模型与接触 Jacobian 正确；刚性冲击和点/面接触近似会在实机上产生误差；gap 收敛不保证落入安全 basin；成本权重可让数学可行轨迹出现高力矩、足滑或自碰撞。warm start 与正则化状态也会影响运行时间尾部。

安全上，离线 FDDP 输出必须经过摩擦、力矩、速度、自碰撞和接触冲击检查。在线使用需设置最大迭代和 deadline miss 行为，并准备可信 fallback controller；求解失败时保持上一控制可能同样危险，必须按机器人状态定义降级策略。

## 可执行但有边界的结论

Crocoddyl 是理解现代 WBC 优化栈的重要经典锚点：它展示如何把接触动力学、流形状态、解析导数和 gap-aware shooting 组合成高效工具。FDDP 特别适合差初始化和高动态接触切换。

“毫秒级”应解读为模型与任务设定下的优化吞吐，不是实机安全认证。加入真实不等式、模型不确定性和闭环跟踪后，性能与成功率必须重新测量。

## 复现与验收清单

锁定官方提交、Pinocchio、编译器、BLAS、线程数、CPU、机器人模型和 contact sequence。复现 Figure 2 时保存每次迭代的总 gap、cost、步长、正则化和接受状态，并与 DDP 使用完全相同初值。

为每类步态和跳跃报告节点数、时间步、迭代次数分布与端到端时间，而非只报最佳单迭代频率。增加差 warm starts、质量/惯量偏差和接触时刻扰动，检查收敛率与尾延迟。

再加入摩擦锥、法向力、关节位置/速度/力矩和自碰撞约束，报告最大违例与裕量。仿真闭环跟踪通过后，硬件按静态接触、慢步、系留动态动作分级，任何优化 deadline miss 都触发明确 fallback。

为了确认缺陷机制而不是偶然权重起作用，可以设计三组初值：准静态插值、故意错误的落脚位置、带明显速度不连续的状态节点。对每组同时运行传统方法和 FDDP，比较收敛成功率、最终代价、最大缺陷与总时间。若只挑一条能收敛的初值，无法证明鲁棒吸引域扩大。

缺陷也应按物理量分解。位置、旋转、线速度和角速度的量纲不同，简单总二范数会掩盖某一类严重不连续。报告每类最大值并用明确尺度归一化，才能判断“缺陷已关闭”是否意味着落脚前后速度与姿态都连续，而不是某个大权重维度主导数值。

接触切换是最需要单独检查的节点。对每次触地保存碰撞前后速度、法向冲量、切向冲量、动量变化和能量损失；对离地保存法向力是否回到零。优化成本下降而出现吸能异常或拉地的接触力，说明模型与约束仍不适合执行。

成本权重必须纳入版本控制。质心、足位姿、姿态和控制正则之间的相对尺度会改变动作风格，也会影响求解难度。调权重后重新跑同一批初值，记录每项代价贡献，而不是只保留总值；否则很容易通过降低某项权重“改善”收敛。

在线模型预测控制还要区分平均时延与尾时延。即使大多数迭代快于周期，偶发正则化增加或线搜索重试也可能错过截止时间。应报告分位数、最大值和连续超时次数，并在控制周期开始前决定本轮最大迭代预算，避免求解器占用不受控。

降级控制不只是“使用上一条轨迹”。机器人处于接触切换时，上一轨迹的接触模式可能已经过期。更稳妥的设计是准备按当前接触状态选择的稳定控制器，并对状态误差、剩余支撑和轨迹年龄设门限；超过门限时进入受控降级或停机。

最后，代码性能数字应在发布构建、固定线程和固定处理器频率下测量，先预热内存分配与缓存。一次最佳值容易受加速频率和缓存影响；公开中位数、九十五分位和问题维度，才能让后续项目判断工具是否满足自己的频率预算。这好比测量车辆通勤时间，不能只记录一路绿灯的最快一趟。

当求解器作为动作生成器而非在线控制器时，还应保存局部反馈增益，而不只保存名义状态与控制。开环轨迹对模型误差十分脆弱，反馈增益能够揭示哪些阶段需要强校正；若增益异常大，通常意味着轨迹靠近奇异接触或代价尺度失衡。回放时比较名义控制、反馈修正和最终饱和量，可以提前发现表面可行但闭环难跟踪的动作。

对不同动作使用同一组代价权重是论文的简洁证据，却不代表生产系统必须坚持统一权重。更合理的机制是公开每类任务的权重变化、变化理由和通过的共同安全约束。把风格参数和安全约束分层，前者允许随任务调节，后者不得为了收敛而降低。

数值正确性还应通过导数检查。选取随机状态、控制和接触配置，把解析导数与小步长有限差分比较，并覆盖接触获得、保持和冲击三类节点。导数检查只用于测试，正式求解仍使用解析形式；若误差集中在某类节点，应先修模型而不是增大正则化掩盖问题。

> **工程判断**：允许早期轨迹留缝，是为了最终更可靠地闭合动力学；它从未允许安全约束留白。
