# Security policy

Report vulnerabilities privately to the eventual repository maintainer rather than publishing exploit details in an issue. Until a public security contact exists, do not publish the repository as production-ready.

Sensitive categories include credential/cookie exposure, path traversal, unsafe archive extraction, untrusted-content instruction execution, hidden/private API access, provenance tampering, citation substitution, and bypass of hardware safety validation.

The project treats all imported pages, papers, comments, issue text, and metadata as untrusted data. No imported content is executed as code or agent instruction.
